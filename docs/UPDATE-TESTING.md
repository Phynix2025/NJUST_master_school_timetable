# 更新功能验收

v2.2.0 的更新检查与地图页面已经用户真机确认。正式包 versionCode 为 6，此前 Debug 测试包为 5；两者版本名均为 2.2.0，以内部版本号判断升级。

## 本次真机测试

使用 `dist/debug/KeZaiZhangXin-v2.2.0.apk` 覆盖安装，入口在课表右上角 `⋮` → **检查更新**。同一签名覆盖安装可保留既有数据。

1. 确认更多菜单显示 v2.2.0，顶部按钮不重叠，周课表和已有笔记、图片正常。
2. 联网检查，出现“正在连接 GitHub…”。如果公开版本仍是 v2.1.0，应提示“没有可用的新版本”，不会要求降级。
3. 断网检查，应提示连接失败或超时，可重试，不能显示“已是最新版本”。
4. 点击“版本发布页”，应在外部浏览器打开本项目 Releases；不在带 Android 桥接的 WebView 中加载外部页面。
5. 重复点击、关闭弹窗、切换应用或旋转屏幕，课表应继续正常使用。

正式发布后，保留旧 Debug 测试包（versionCode 5）的设备可以检查到正式包（versionCode 6），用于验证下方下载及安装链路。已安装正式包的设备需要等更高 versionCode 的版本；不会伪造版本或绕过安装校验。

## 完整升级链路验收清单（尚待设备验证）

- 新版本弹窗显示版本、日期、大小和更新说明；“暂不更新”不启动下载。
- 移动网络／计费网络弹出下载确认。
- 下载进度随时间变化，可后台下载、取消；重启应用后恢复系统下载任务进度。
- 网络中断后显示等待网络或失败重试；空间不足时提示原因。
- 下载完成后可选择稍后安装，不会自动安装；再次打开更多菜单可继续安装。
- 缺少安装授权时打开本应用的系统授权页，返回后重新确认安装；拒绝授权可继续用旧版。
- 在系统安装器取消后仍保留 APK；重复安装前再次校验。
- 缺失／损坏文件、SHA-256 不匹配、错误包名、错误签名、版本不符和系统不兼容均不交给安装器。
- 覆盖升级成功，新应用启动时清理更新目录内已安装 APK，并提示成功；笔记、课表、图片引用及凭据保留。
- 从未通过应用下载的浏览器下载目录文件不应被删除。
- 更新后课程通知继续工作。

## 更新源与发布约定

只读取本仓库的最新正式 Release。每次发布应同时包含 APK、`.sha256` 和 `update.json`。Release 的标签去掉 `v` 后必须等于 `update.json.versionName`。

```powershell
.\gradlew.bat :app:assembleRelease
.\tools\prepare-update.ps1 -Variant release
```

产物位于 `dist/release/`。此脚本仅生成文件，不上传、不发布。为 Debug 测试打包时使用 `-Variant debug`，产物位于 `dist/debug/`，不要把 Debug 文件当正式 Release 上传。

`update.json` 包含 `versionCode`、`versionName`、`minSdk`、`apk`、`size` 和 `sha256`，由构建元数据与 APK 自动生成。`versionCode` 必须递增，签名必须保持一致。不要手动篡改 JSON 中的版本去模拟新包，APK 的实际版本也会被校验。

## 自动化检查

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm test
```

JVM 测试验证稳定版版本比较、受信任附件地址、SHA-256 格式；浏览器测试验证课表与更多菜单桥接入口。它们不能代替系统下载管理器、安装授权和覆盖升级的真机验收。
